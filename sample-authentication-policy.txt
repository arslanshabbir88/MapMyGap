=== AUTHENTICATION ASSURANCE LEVELS (AAL) ===

AAL1 - SINGLE-FACTOR AUTHENTICATION
Control ID: AAL1.1
Description: Permitted Authenticator Types for AAL1
Implementation Status: IMPLEMENTED
Evidence: Username and password combinations serve as the primary single-factor authentication method across all applicable systems and applications. Password complexity requirements include minimum 12 characters, mixed case letters, numbers, and special characters. Passwords are salted and hashed using PBKDF2 with minimum 10,000 iterations.

Control ID: AAL1.2  
Description: Authenticator and Verifier Requirements
Implementation Status: IMPLEMENTED
Evidence: Strong password policies enforced including 90-day expiration, account lockout after 5 failed attempts for 30 minutes, and replay resistance through TLS v1.2+ encryption. All password storage uses bcrypt with minimum cost factor of 12.

Control ID: AAL1.3
Description: Reauthentication Requirements
Implementation Status: IMPLEMENTED
Evidence: 30-minute inactivity timeout for general user sessions, 4-hour reauthentication for Moderate/High/Critical assets, and 1-hour reauthentication for privileged access sessions. Operating systems enforce 15-minute inactivity screen lock.

AAL2 - MULTI-FACTOR AUTHENTICATION
Control ID: AAL2.1
Description: Permitted Authenticator Types for AAL2
Implementation Status: IMPLEMENTED
Evidence: Hardware Security Keys (FIDO2/WebAuthn like YubiKey, Google Titan) are approved for AAL2. Platform Authenticators including Windows Hello for Business with TPM and Apple Touch ID/Face ID are configured. Cryptographic Smart Cards (PIV/CAC) and Time-based One-Time Password (TOTP) applications are available.

Control ID: AAL2.2
Description: Authenticator and Verifier Requirements
Implementation Status: IMPLEMENTED
Evidence: Identity Provider (IdP) configured to enable and prioritize approved AAL2 authenticator types. Conditional access policies enforce AAL2 for High/Critical assets. Comprehensive procedures documented for authenticator provisioning, enrollment, user training, and lifecycle management.

Control ID: AAL2.3
Description: Reauthentication Requirements
Implementation Status: IMPLEMENTED
Evidence: AAL2 mandated for High and Critical assets with 4-hour reauthentication for classified asset access and 1-hour reauthentication for privileged access sessions. Network context changes trigger immediate reauthentication.

AAL3 - HIGHEST ASSURANCE AUTHENTICATION
Control ID: AAL3.1
Description: Permitted Authenticator Types for AAL3
Implementation Status: NOT IMPLEMENTED
Evidence: No AAL3 authenticator types currently defined or implemented.
Recommendation: Define and document permitted authenticator types for AAL3, including specific technologies and configurations if AAL3 is required for organizational assets.

Control ID: AAL3.2
Description: Authenticator and Verifier Requirements
Implementation Status: NOT IMPLEMENTED
Evidence: No authenticator or verifier requirements specified for AAL3.
Recommendation: Establish detailed authenticator and verifier requirements for AAL3, including cryptographic specifications, hardware security module (HSM) usage, and secure channel requirements.

Control ID: AAL3.3
Description: Reauthentication Requirements
Implementation Status: NOT IMPLEMENTED
Evidence: No reauthentication requirements specified for AAL3.
Recommendation: Define specific reauthentication requirements for AAL3, including shorter reauthentication intervals and re-verification of authenticator possession.

=== GENERAL AUTHENTICATION CONTROLS ===

Control ID: AAL_GEN.1
Description: Security Controls
Implementation Status: IMPLEMENTED
Evidence: Comprehensive security controls implemented including strong password policies, replay resistance, account lockout mechanisms, memorized secret compromise checking, reauthentication mechanisms, MFA for remote access, physical access controls, and security awareness training.

Control ID: AAL_GEN.2
Description: Records Retention Policy
Implementation Status: PARTIAL
Evidence: Log retention periods defined for various authentication logs: 90 days for remote access, 90 days online/1 year offline for AAL1 reauthentication logs, 90 days for AAL2 authentication logs, 365 days for SIEM logs. However, some references point to appendices not provided.
Recommendation: Consolidate and clearly define comprehensive records retention policy for all authentication-related logs and records.

Control ID: AAL_GEN.3
Description: Privacy Requirements
Implementation Status: NOT IMPLEMENTED
Evidence: While HIPAA privacy requirements for PHI are addressed, specific privacy requirements for authentication data collection, storage, use, or sharing are not explicitly detailed.
Recommendation: Develop specific privacy requirements for authentication data, addressing user consent, data minimization, and protection of sensitive authentication information.

Control ID: AAL_GEN.4
Description: Redress Requirements
Implementation Status: NOT IMPLEMENTED
Evidence: Redress process exists for denied PHI access requests, but no general redress mechanism for authentication-related issues.
Recommendation: Establish formal redress process for authentication-related issues, allowing users to appeal authentication decisions or report problems with authenticators.
